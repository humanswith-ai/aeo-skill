# /aeo — проектировщик запросов под нейросети (AEO/GEO)

Скил для Claude Code: проектирует систему автономных, цитируемых запросов под ответы нейросетей (ChatGPT, Perplexity, YandexGPT, Google SGE) — по этапам воронки и/или по возможностям продукта.

**Это НЕ SEO и НЕ копирайтинг.** Роль — AEO/GEO-архитектор: конструирует запросы, из которых нейросети смогут извлечь готовый ответ и процитировать источник.

## Главный тест

> «Задал бы это реальный человек нейросети — и можно ли дать на это цитируемый ответ без дополнительного контекста?» Если нет — элемент невалиден.

## Сценарий работы (v0.2.0)

| # | Этап | Суть |
|---|---|---|
| 0 | Входящая задача | `/aeo спроектируй запросы под проект <URL>` |
| 1 | Бриф — 9 полей | проект, услуга, объект, гео, аудитория, язык, тип продукта, персона, **запросы от клиента** (= интенты, не формулировки) |
| 2 | **Изучение продукта — до любой генерации** | главная → страница продукта из брифа → позиционирование/«О нас» → карта возможностей |
| 3 | Формат | поисковые запросы или темы статей — не смешивать |
| 4 | Buyer Persona | одна на прогон; «меняем покупателя» → полная перестройка |
| 5 | Структура | по этапам воронки (Awareness/Consideration/Evaluation/Decision) и/или по возможностям продукта; кластеры по 5 |
| 6 | Генерация | через 5 законов AEO; стиль подач — ситуативно, калибровка на 2–3 примерах |
| 7 | Чек-лист | 7 пунктов самопроверки |
| 8 | Выдача | один этап за раз → ждать подтверждения |
| 9 | Цикл правок | точечно; после второго «не то» — калибровка на примерах, не слепое переписывание |

## 5 законов AEO

1. **Живой запрос, а не маркетинговый заголовок** — как человек печатает, а не как редактор пишет подзаголовок
2. **AEO-якорь в каждом запросе** — запрос ведёт к услуге/продукту, «безродных» нет
3. **Привязка к реальному продукту** — от модулей и функций, не от абстракции
4. **География — только где меняет ответ** — регуляции, data residency, локальные движки
5. **Без хайпа, брендов, политики и мета-уровня**
